# 숨은길 공모전 전체 검수 보고서 — 2026-08-28

## 결론

프론트엔드 프로덕션 빌드와 새 데모 홈은 통과했다. 다만 현재 로컬 환경은 백엔드 의존성과 배포용 환경 변수가 준비되지 않아 공모전 핵심인 실제 OpenAPI 연동·추천·혼잡도 흐름을 끝까지 재현하지 못했다. 제출 전 가장 먼저 해소해야 할 것은 디자인이 아니라 실행 환경 복구와 실데이터 시연 증빙이다.

## 우선순위 이슈

### P0 — 제출 전 필수

1. **백엔드 재현 환경이 없다.** 현재 셸에는 프로젝트 의존성이 없어 검증 스크립트 20개를 실행할 수 없다. 깨끗한 가상환경 또는 Docker 환경을 복구한 뒤 전부 재실행해야 한다.
2. **실데이터 시연을 확인하지 못했다.** 대회는 관광공사 OpenAPI 실제 연동과 안정적 시연이 핵심인데, 환경 변수와 백엔드 부재로 TourAPI/DataLab 응답을 검증하지 못했다.
3. **배포 설정이 완성되지 않았다.** `deploy/.env`가 없고 `NEXT_PUBLIC_API_BASE`, `NEXT_PUBLIC_TMAP_APP_KEY`, `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`가 비어 있다.

### P1 — 완성도에 직접 영향

1. **기존 홈의 실패 상태가 너무 비어 보인다.** 백엔드가 꺼지면 검색 아래 핵심 영역이 큰 어두운 플레이스홀더처럼 남고, 추천 콘텐츠는 조용히 사라진다. 심사 현장에서 API가 지연될 경우 서비스가 미완성처럼 보일 수 있다.
2. **첫 화면에서 지정과제의 인과관계가 약하다.** 검색과 10개 퀵메뉴가 먼저 보여 “과밀 관광지 → 한적한 대안 → 코스”가 한 번에 읽히지 않는다. 새 데모는 이 흐름을 하나의 경로 장면으로 합쳤다.
3. **린트가 자동화되지 않는다.** `npm run lint`가 대화형 초기 설정에 진입한다. ESLint 설정 파일과 비대화형 스크립트를 확정해야 CI에서 회귀를 잡을 수 있다.

### P2 — 제출 품질 보강

1. **법적·오류 페이지가 불완전하다.** 개인정보처리방침은 있지만 이용약관 라우트와 브랜드형 `not-found.tsx`가 없다.
2. **소셜 공유 메타가 부족하다.** 루트 메타데이터에 Open Graph 이미지와 공유용 메타가 없다.
3. **현황 문서가 오래됐다.** 루트 `STATUS.md`의 최종 갱신은 2026-07-24로, 8월 구현 상태를 대표하지 못한다.
4. **기존 컴포넌트의 빈 대체 텍스트를 재분류해야 한다.** 검색 결과 9건은 장식 이미지일 수도 있지만, 스팟·비교 카드처럼 의미 있는 사진은 구체적인 대체 텍스트가 필요하다.

## 홈 디자인 비교

### 현재 홈

- 장점: 기능 접근성이 높고 지역 검색·메뉴·추천이 모두 연결돼 있다.
- 약점: 포털형 정보 구조라 공모전 문제 해결 스토리가 분산된다. 데이터 실패 시 첫 화면의 공백이 크다.

### 새 데모 홈 (`/demo-home`)

- 한 문장 입력을 중심으로 “해운대 82% → 기장 18% → 동네 3곳”의 변화를 첫 화면에서 보여준다.
- 지도 경로 리본과 로컬 일러스트를 시그니처로 사용하고, 수치 근거·코스·지역 파급효과 순으로 스토리를 압축했다.
- 기존 API나 저장 구조를 바꾸지 않은 독립 데모이며, CTA는 실제 `/course`, `/congestion`, `/onboarding` 라우트로 연결된다.
