# 05-benchmark-plan — 대한민국 구석구석 벤치마킹 → 숨은길 단계별 개선 플랜

- **문서 버전**: v1.0
- **작성**: planning-lead
- **작성일**: 2026-07-24
- **성격**: 한국관광공사 공식 국내여행 포털 **"대한민국 구석구석"(korean.visitkorea.or.kr)**을 벤치마킹해, 흡수할 장점/버릴 단점을 가려 **AI company 단계별(Phase) 개선 플랜**으로 정리한다.
- **근거**: 오케스트레이터의 구석구석 실분석(WebFetch 확인분), 우리 현황(`STATUS.md`, `02-roadmap.md`, `01-interface-contract.md` 부록 A~H).
- **불변 방침 승계**(02-roadmap §0): B안 디자인 고정·additive, 무료 API 한도(Tmap 1,000/일·공공 1,000/일), 법률 보류(실사용자 공개 전), 새 유료키 금지·비용 0. **여기 적힌 흡수 항목은 전부 우리가 이미 가진 무료 데이터/API로 가능한지 정직히 판정했고, 안 되는 것은 "데이터 없음"으로 배제**했다.

---

## 0. 한 줄 결론

구석구석은 **콘텐츠 폭(축제·코스·큐레이션·게이미피케이션)은 넓지만 정보 과다·약한 CTA·진부한 UI**로 사용자를 지치게 한다. 숨은길은 **개인화·과잉관광 해소·깔끔한 B안**으로 이미 앞서 있으나, **코스(순서 있는 하루 일정)·큐레이션·축제 실연동·가벼운 게이미피케이션**이 비어 있다. 이 빈칸을 **구석구석을 그대로 베끼지 않고 숨은길 컨셉으로 재해석**해 Phase 1~4로 채운다.

## 1. 한눈 비교표 (항목별 우열)

| 항목 | 대한민국 구석구석 | 숨은길(현재) | 판정 |
|---|---|---|---|
| **여행 코스** | "1분이면 끝" 맞춤 코스 생성 + 월간 Best 30 코스. **강점** | 저장코스(localStorage 스팟 목록)만. **순서·동선·소요시간 없음** | **진 곳** → Phase 1 |
| **큐레이션** | 다층(월간 Best 30, 지역/테마별, 맛집차트). **강점** | 발견형 홈(featured)·추천 목록. 테마 컬렉션 없음 | **진 곳(부분)** → Phase 2 |
| **AI 활용** | AI 요약(여행기사·후기 자동 요약) | 로컬 LLM 취향 추출 + 맞춤 스코어링 + 로드밸런싱. **개인화 깊이는 우리 우위** | **이긴 곳** (요약은 우리에 없음 → Phase 2 보강) |
| **검색·지역분류** | 검색·지역분류 약함(내비 모호). **약점** | 지역검색(regions/search)·칩·카테고리 필터·정렬 4종 | **이긴 곳** |
| **게이미피케이션** | 디지털관광주민증·배지랜드·스탬프. **강점(참여 유도)** | 없음 | **진 곳** → Phase 4(가벼운 버전) |
| **축제/이벤트** | 축제달력 실연동 | 홈 축제 **배너 정적**(미연동) | **진 곳** → Phase 3 |
| **UI·정보구조** | 정보 과다(9개 빠른메뉴+다중 섹션)·시각 우선순위 불명확·진부. **약점** | 깔끔한 B안·모바일 우선·시각 우선순위 명확 | **이긴 곳(우리 핵심 자산)** |
| **CTA** | "더보기"만 반복, 약함. **약점** | 발견형 CTA는 있으나 기능 진입 유도 점검 필요 | 무승부 → Phase 3에서 우리 CTA 강화 |
| **차별점(과잉관광)** | 없음(오히려 인기 집중 조장) | **과잉관광 해소(로드밸런싱·숨은길 컨셉)** | **압도적 이긴 곳** → Phase 전반에서 계속 부각 |
| **개인화** | 취향 기반 약함(코스는 조건 선택식) | **로컬 LLM 취향 추출 → 벡터 스코어링** | **이긴 곳** |

**요약**: 우리가 진 4칸(코스·큐레이션·게이미피케이션·축제)은 전부 **우리 기존 무료 데이터로 메울 수 있다**. 이긴 칸(개인화·과잉관광·깔끔 UI)은 **더 부각**한다.

## 2. 흡수(Adopt) — 구석구석에서 가져올 것 (숨은길 식 재해석)

> 원칙: 그대로 베끼지 않는다. **숨은길 컨셉(과잉관광 회피)+B안 깔끔 UI+개인화**로 다시 짠다. 각 항목 옆에 **데이터 가능성**을 정직 표기.

| # | 구석구석 원본 | 숨은길 식으로 어떻게 | 데이터 가능성(정직) |
|---|---|---|---|
| **A1** | "1분 맞춤 코스 생성" | **AI 추천 코스** — 온보딩 취향으로 **순서 있는 하루 코스**(카테고리 엮기: 관광지→맛집→카페/산책)를 짜고, **저혼잡 우선(로드밸런싱 내장)** + **Tmap 도보/차 소요시간·경로선**. 구석구석 대비 개인화+과잉관광 회피+길안내가 얹힌 상위 버전 | **가능** — 온보딩 프로필·스팟 스토어·혼잡도·Tmap Route(무료 1,000/일)로 성립. 새 키 불필요 |
| **A2** | AI 요약(기사·후기) | **스팟 상세 소개글 3줄 요약** — TourAPI `overview`(길고 딱딱한 소개글)를 **로컬 LLM으로 3줄 핵심 요약** + "이런 분께 추천" 한 줄. 우리 기존 로컬 LLM 재사용 | **부분 가능** — 소개글 요약은 가능. **후기/기사 요약은 우리에게 후기·기사 데이터가 없어 배제**(지어내지 않음) |
| **A3** | 다층 큐레이션(Best 30, 테마별) | **테마 컬렉션** — "혼잡도 낮은 숨은 명소", "반려동물 동반 베스트", "비 오는 날 실내" 등 우리 `themes` 플래그·혼잡도로 묶은 큐레이션 카드. **Best "랭킹"이 아니라 "숨은 정도·저혼잡" 기준 큐레이션**(우리 컨셉) | **가능** — 스팟 스토어 `themes`·`is_hidden_gem`·혼잡도로 필터링. **인기순 "차트"는 인기 지표가 없어 배제**, "숨은/한적" 기준으로 대체 |
| **A4** | 축제달력 | **축제 실연동** — 홈 정적 배너를 TourAPI 축제공연행사(`contentTypeId=15`, festival 날짜)로 승격. 날짜·지역 필터. **혼잡 예상 축제엔 "대신 근처 숨은길" 연결**(우리 컨셉) | **가능성 높음(실호출 확인 필요)** — TourAPI 축제공연행사가 기존 `PUBLIC_DATA_API_KEY`로 되는지 backend 실호출 확정 필요. 안 되면 행안부 표준데이터 무료 활용신청(CEO 액션) |
| **A5** | 배지랜드·스탬프·관광주민증 | **가벼운 방문 스탬프** — 사용자가 다녀온/가고 싶은 스팟에 **스탬프 찍기(localStorage)** + "숨은길 N곳 발견" 배지. **개인정보·위치·사진 없이** 참여감만 | **가능(경량)** — localStorage 기반이라 개인정보 0. **위치·사진 방문인증(M8)은 위치정보법·초상권으로 이번 범위 밖**(보류 유지) |
| **A6** | 여행가이드북 | **여행팁 → 큐레이션 가이드** — 현재 placeholder 여행팁을 content-marketer가 "저혼잡 여행 요령·숨은길 활용법" 가이드로 채움 | **가능** — 정적 콘텐츠. 과대광고·법률 리스크 금지 톤 |

## 3. 버릴 것(Avoid) — 답습하면 안 되는 구석구석 약점 + 우리 자가점검

| # | 구석구석 약점 | 우리가 절대 하지 말 것 | 우리 사이트 자가점검 |
|---|---|---|---|
| **V1** | **정보 과다**(9개 빠른메뉴+다중 섹션 → 선택 마비) | 코스·큐레이션·축제·스탬프를 홈에 **한꺼번에 쏟지 않는다**. 홈은 발견형 1축 유지, 신규 기능은 **별도 진입점/탭** | **주의 징후 있음** — 홈에 이미 전광판+featured+축제배너+검색. Phase마다 홈에 섹션 추가 금지, 정보구조 정리(Phase 3)에서 위계 재점검 |
| **V2** | **약한 CTA**("더보기"만 반복) | "더보기" 남발 금지. 각 카드에 **행동 유도**("이 코스로 하루 짜기", "혼잡 피해 여기로") | 점검 필요 — Phase 3에서 CTA 문구 강화(content-marketer) |
| **V3** | **기능 진입 전 설명 부족** | 코스/온보딩 진입 전 **한 줄 가치 설명**("취향만 넣으면 붐비지 않는 하루 코스"). 빈 화면에 던지지 않기 | Phase 1 코스 진입부·온보딩 카피 보강 |
| **V4** | **진부한 UI·시각 우선순위 불명확** | B안 깔끔함을 **희석하지 않는다**. 신규 화면도 기존 토큰·컴포넌트만 사용(새 디자인 언어 금지, P-1) | 양호 — additive 규칙으로 이미 방어됨. 유지가 곧 우위 |
| **V5** | **인기 집중 조장**(Best 랭킹이 혼잡 유발) | "인기순 차트"를 무비판 이식하지 않는다. 우리는 **저혼잡·숨은 기준**으로 큐레이션(A3) | 우리 컨셉과 정면 배치 — 랭킹형 큐레이션 배제 근거 |

## 4. 지킬 차별점(Keep) — 우리 강점을 더 부각

| # | 우리 강점 | 더 부각할 방법 |
|---|---|---|
| **K1** | **과잉관광 해소**(로드밸런싱·숨은길) | 코스·축제·큐레이션 **전 기능에 "붐비는 곳 대신 여기" 라인을 일관 삽입**. 이게 구석구석이 절대 못 하는 브랜드 축 |
| **K2** | **로컬 LLM 개인화** | 코스(A1)·요약(A2)에 온보딩 프로필을 재소비 → "당신 취향 기반"을 화면에 명시. 구석구석의 조건선택식보다 깊음 |
| **K3** | **깔끔한 B안·모바일 우선** | 정보 과다(V1) 반면교사로 **여백·1축 발견형**을 유지하는 것 자체가 차별점. Phase마다 "홈에 안 쏟기" 규율 |
| **K4** | **정직성**(예측치 고지·데이터 없음 정직표기·과대광고 금지) | 구석구석의 과장 없는 신뢰 톤. 코스 소요시간도 "예상", 요약도 "AI 요약" 고지 |

## 5. 단계별 실행 플랜 (Phase 1~4)

> 우선순위 순. 각 Phase는 **혼자서도 로컬에서 보이는** 단위. 계약은 착수 직전 `01-interface-contract.md`에 부록(I, J, …)으로 additive 확정. 무료 한도·비용 0·법률 보류 준수. **대표 액션 필요분은 §6에 분리**.

### Phase 1 — AI 추천 코스 + Tmap 길안내 ★ 이미 착수 예정 (최우선)

- **한 줄**: 온보딩 취향 → **순서 있는 하루 코스**(관광지→맛집→카페/산책, 저혼잡 우선) + **Tmap 도보/차 소요시간·경로선**. 구석구석 "1분 코스"의 상위 버전(개인화+과잉관광 회피+길안내).
- **흡수 항목**: A1. **차별점 K1·K2 집약** — 프로젝트의 얼굴.
- **재사용(새로 안 만듦)**: 온보딩 프로필(MVP-3), 스팟 스토어·스코어링(MVP-4), 혼잡도(MVP-2), 로드밸런싱(MVP-7), Tmap 지도(MVP-6). **새 유료키 0**.
- **부서 분담**:
  - **backend** — `POST /api/v1/course/generate`(프로필+region→순서 있는 스팟 시퀀스). 코스 조립 규칙(카테고리 엮기·저혼잡 우선·시간대 배분). **Tmap Route API 프록시**로 구간 소요시간·경로좌표 확보 → **결과 캐시**(무료 1,000/일). 실패 시 직선거리 폴백(`path_source:"straight"`).
  - **ai** — 코스 시퀀싱 로직(스팟 fit 재사용 + 동선/카테고리 순서 규칙). **새 LLM 호출 없음**(결정론 조립, 인젝션 표면 0 유지).
  - **designer** — B안 코스 화면(타임라인 카드 + 지도 경로선 + 구간 소요시간). 진입 전 한 줄 가치 설명(V3).
  - **frontend** — 코스 화면 라우트, 타임라인 UI, Tmap polyline, "이 코스로 하루 짜기" CTA(V2).
- **계약**: 부록 I(착수 직전 확정).
- **검수 등급**: **풀검수** — 신규 핵심 기능 + 외부 API(Tmap Route) 신규 연동. QA+security 병렬(serviceKey/Tmap키 서버 전용 확인).
- **DoD**: 온보딩 후 코스 화면에서 "오전 관광지 → 점심 맛집 → 오후 한적한 산책로" 순서 카드가 뜨고, 지도에 경로선+구간 소요시간이 그려지며, 붐비는 스팟은 대안으로 대체된다.
- **대표 액션**: Tmap Route API가 기존 Tmap 키로 무료 되는지 backend 실호출 확인(안 되면 §6).

### Phase 2 — AI 상세 요약(A2) + 테마 큐레이션 컬렉션(A3)

- **한 줄**: 스팟 상세의 딱딱한 소개글을 **로컬 LLM 3줄 요약**하고, 홈/탐색에 **"저혼잡 숨은 명소"·"반려동물 베스트" 같은 테마 컬렉션**을 얹는다.
- **흡수**: A2, A3. **차별점 K2·K1**.
- **부서 분담**:
  - **backend** — 상세 응답(부록 G)에 `summary` 필드 additive(로컬 LLM 요약, **배치/캐시** — 요청마다 LLM 호출 금지). `GET /api/v1/collections`(테마별 큐레이션: themes/is_hidden_gem/혼잡도 필터 조합).
  - **ai** — 소개글 요약 프롬프트(로컬 Ollama, `format` 강제, 원문 그대로 렌더 금지·요약만). 인젝션 방어는 온보딩과 동일 구조.
  - **designer** — 상세 요약 블록, 컬렉션 카드 섹션(홈 아님, 별도 탐색 탭 — V1 방어).
  - **frontend** — 요약 표시("AI 요약" 고지, K4), 컬렉션 라우트.
- **계약**: 부록 J.
- **검수 등급**: **약식**(QA 단독) — LLM 요약은 기존 온보딩 인젝션 방어 패턴 재사용이라 신규 시크릿·개인정보 없음. 단 **LLM 원문 렌더/프롬프트 인젝션 정황 시 풀 승격**.
- **DoD**: 상세 화면에 3줄 요약이 뜨고, 탐색에서 "혼잡도 낮은 숨은 명소" 컬렉션 카드가 실데이터로 렌더.

### Phase 3 — 축제 실연동(A4) + 홈 정보구조 정리·CTA 강화(V1/V2/V3)

- **한 줄**: 정적 축제 배너를 **실연동 축제달력**으로 승격하고, 그동안 늘어난 홈 섹션의 **위계를 재점검**하며 CTA 문구를 강화한다.
- **흡수**: A4. **반면교사 V1·V2·V3 정면 대응**.
- **부서 분담**:
  - **backend** — `GET /api/v1/festivals`(TourAPI 축제공연행사 실연동, 날짜/지역 필터, 배치/캐시). **실호출로 기존 키 가능 여부 확정**(안 되면 §6).
  - **designer** — 홈 정보구조 재점검(1축 발견형 유지, 신규 섹션 위계 정리 — 정보 과다 방어), 축제 카드.
  - **content-marketer** — CTA 카피 강화("더보기" 제거→행동 유도), 진입 전 한 줄 설명.
  - **frontend** — 축제달력 UI, 개편된 CTA.
- **계약**: 부록 K.
- **검수 등급**: **약식**(QA 단독) — 읽기 전용 공공 API + 카피/레이아웃. 시크릿 하드코딩만 확인.
- **DoD**: 홈/축제 탭에 실제 축제(날짜·지역)가 뜨고, 혼잡 예상 축제엔 "근처 숨은길" 연결이 붙으며, 홈이 정보 과다 없이 정돈됨.

### Phase 4 — 가벼운 방문 스탬프·배지(A5) + 여행 가이드(A6)

- **한 줄**: 개인정보 없는 **localStorage 스탬프/배지**로 참여감을 주고, 여행팁을 **저혼잡 여행 가이드**로 채운다.
- **흡수**: A5, A6. **차별점 K1(숨은길 발견 배지)**.
- **부서 분담**:
  - **frontend** — 스탬프 찍기/배지("숨은길 N곳 발견") localStorage(`sumeungil:stamps:v1`), 저장코스 화면 연계. **서버·위치·사진 없음**.
  - **content-marketer** — 여행 가이드 문구(과대광고·법률 리스크 금지 톤, K4).
  - **designer** — 배지/스탬프 비주얼(B안 토큰).
- **계약**: 부록 L(프론트 단독이라 경량).
- **검수 등급**: **생략~약식** — 순수 프론트 localStorage + 정적 콘텐츠. 오케스트레이터 직접검증. 개인정보 0 확인.
- **DoD**: 스팟에 스탬프를 찍으면 배지가 누적되고 새로고침해도 유지되며, 가이드 문구가 카테고리별로 렌더.
- **범위 밖(명시)**: 사진·위치 기반 방문 인증(M8), 디지털관광주민증 같은 실명/위치 기능은 **위치정보법·초상권으로 이번에도 제외**(착수 시 security+legal 필수).

## 6. 대표(CEO) 액션 항목 — 자율로 못 하는 것

| # | 액션 | 어느 Phase가 켜지나 | 정직한 현재 상태 | 미승인 시 |
|---|---|---|---|---|
| CEO-B1 | **Tmap Route API 무료 쿼터/도메인 확인** | Phase 1 | Tmap JS SDK 키는 있음. Route API가 **같은 키로 무료 1,000/일 되는지 backend 실호출로만 판정**(추측 금지). 대부분 동일 키로 열림 | 직선거리·소요시간 근사 폴백(`path_source:"straight"`)으로 코스는 뜨나 실도로 경로선 없음 |
| CEO-B2 | **TourAPI 축제공연행사 접근 확인/추가 활용신청** | Phase 3 | 기존 `PUBLIC_DATA_API_KEY`로 되는지 backend 실호출 확정 필요. 안 되면 data.go.kr에서 **무료 활용신청**(축제공연행사 or 행안부 표준데이터). 비용·운영계정 전환 없음 | 축제 배너 정적 유지(현행), Phase 3의 나머지(홈 정리·CTA)는 진행 |
| CEO-B3 | **사진/위치 방문 인증 착수 여부** | (범위 밖) | A5는 개인정보 없는 경량 스탬프로 대체. **본격 인증(M8)은 위치정보법·초상권 재검토 전 착수 금지** | 경량 스탬프로 참여감 확보, 본격 인증 보류 |

> **공통**: 위 3건 모두 **비용 발생·유료 전환·배포는 아니다.** CEO-B1/B2는 "무료 범위 실호출 확인" 수준이라 backend가 착수 시 자동 확인하고 안 되면 폴백/보류로 graceful 진행한다. 실사용자 공개 전 법률 보류(P-3)도 유지.
