## 대표가 직접 해야 할 것

1. **운영 서버 `deploy/.env`에 `ADMIN_SESSION_SECRET` 값이 실제로 있는지 파일을 눈으로 확인.** 없으면:
   ```bash
   python3 -c "import secrets; print(secrets.token_urlsafe(48))"
   ```
   → `.env`에 넣고 `docker compose up -d backend`. (주의: 이 값을 바꾸면 기존 관리자 로그인 세션이 끊기고, 방문 통계의 방문자 해시가 바뀌어 전환 당일 방문자 수가 일시 중복 계산됨 — 정상.)
2. **가비아 DNS**에 TXT 레코드 2개 추가 (메일을 안 쓰는 도메인이라도 사칭 메일 차단용):
   - `@` → `v=spf1 -all`
   - `_dmarc` → `v=DMARC1; p=none;` (모니터링부터, 나중에 quarantine→reject)
3. **배포 결정** — 이번 반영분(+ 다른 세션의 슬랙 봇/Prometheus 작업)을 운영에 올릴지. 배포 후 확인할 것:
   - `docker compose logs backend | grep "ADMIN_SESSION_SECRET 미설정"` → **아무것도 안 나와야 정상**
   - 홈 사진·혼잡도·날씨가 뜨는지 (외부 API https 전환 실호출 확인)
   - 기존 공유 링크 1건이 500 없이 열리는지 (사진·설명은 플레이스홀더가 됨 — 의도)
   - `https://sumeungil.co.kr/.well-known/security.txt` 200
   - `docker compose pull && up -d ollama certbot` 후 ollama 모델 로드 정상 여부

## 알아둘 것 (법률팀 전달 예정)
- 방문집계 90일 자동삭제가 이번에 처음 실제로 동작하게 됐다 → 그 전 기간(2026-08-10~18)은 관리자 화면 안내("90일 후 자동 삭제")와 실제가 달랐다. 데이터 자체는 IP 가명화 집계뿐이라 위험은 낮지만, 처리방침 문구 정합성은 법률팀이 한 번 봐야 함.
