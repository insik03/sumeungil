## 2. A-6 상세 — 공유/저장 코스 payload 재구성

### 기존 구조
`POST /courses/share` 는 `course` JSON 을 **크기(32KB)·중첩깊이(16)만** 검사하고 그대로 보관·반환했다.
`/shared` 피드와 `/course/shared/{code}` 는 공개 URL 이므로, 클라이언트가 API 한 번으로 다음을
우리 도메인 화면에 올릴 수 있었다 — XSS 가 아니라 **콘텐츠 위조**라 텍스트 노드 렌더로는 막히지 않는다.

- 존재하지 않는 장소명·주소·좌표 (`spots[].name` / `.address` / `.location`)
- "여유/한적" 혼잡도 배지 (`spots[].congestion` — 실시간 원천을 사칭)
- 임의 외부 이미지 (`spots[].image_url`)
- "이래서 추천했어요" 칩 문구 (`match_reasons.matched_tags` — 프론트가 라벨 없으면 원문 표시)
- 임의 설명문 (`blurb`), 임의 신규 키(`verified_badge` 등)

### 프론트 계약 확인 (수정 전 조사)
- 생성: `ShareCourseModal.tsx` → `api.ts shareCourse({nickname,title,course})`, `course` 는 `CourseResponse` 원본
- 소비: `SharedCourseDetailContent.tsx` 가 `course.spots[]`(id/name/slot_label/category/themes/congestion/
  image_url/photo_credit/blurb/match_*), `course.legs[i].walk|car`, `course.region.region_name` 을 읽는다.
  `notice`·`ai_summary`·`ai_title` 은 **읽지 않는다**.

### 대응 — "식별자만 신뢰한다"
신규 `backend/app/services/course_payload.py`.

| 필드 | 처리 |
|---|---|
| 스팟 식별자 | `id` / `spot_id` / `content_id` / `contentid` 중 정수 하나만 신뢰 |
| 이름·주소·좌표·카테고리·지역·테마·숨은스팟 | `spot_repo.by_id()` 서버 값으로 **전부 덮어씀** |
| 없는 스팟 id | 쓰기 경로 **400 INVALID_COURSE**(조용히 무시하지 않는다) / 읽기 경로는 그 스팟만 제외 |
| `congestion` | **저장하지 않는다.** 상세 조회 시 `recommend_service._congestion_by_name/_match_congestion` 으로 **지금 값**을 붙인다(`attach_congestion`) → 프론트 계약 불변 |
| `image_url`/`photo_credit`/`blurb` | 클라이언트 값 폐기 후 `course_enrich_service.enrich_course_spots` 로 서버 캐시에서 채움(정상 흐름은 24h 캐시 warm → 원천 호출 0). 읽기 시엔 CDN 호스트(`https://tong.visitkorea.or.kr/`)·고정 출처문구 allowlist 통과분만 |
| `match_reasons` | `tag_registry` 실재 태그값 / 정해진 signal 5종만 통과, 나머지 폐기. 남는 게 없으면 `null` |
| `match_score` | 0.0~1.0 clamp |
| `slot_label` | `clean_user_text` + 24자 (없으면 `"{i+1}번째"`) |
| `ai_title`/`ai_summary` | `clean_user_text` + 40자/400자 (프론트 미표시지만 저장값을 평문으로 유지) |
| `legs` | 길이를 `스팟수-1` 로 강제, `minutes`/`meters` 정수 clamp(≤1440분 / ≤500km), `path` 는 한국 bbox 좌표쌍만(하나라도 이상하면 통째 `null` — 중간이 잘린 경로선은 지도에 거짓 선을 그린다) |
| `total_distance_m` | 클라이언트 값 무시, `legs` 에서 재계산(walk 하나라도 없으면 `null`) |
| `notice` | 폐기(서버가 만든 사실 문장) |
| 그 밖의 모든 키 | 폐기(allowlist) — "공식 인증" 류 배지 필드를 새로 만들 수 없다 |

### 과거 데이터
DB 마이그레이션은 하지 않는다. 대신 **읽을 때도 같은 필터**(`filter_stored_course`)를 태운다.
새 코드가 쓴 payload 에는 `"v": 2` 표식이 있고, 표식이 없는 과거 payload 는 사진·설명을
검증할 근거가 없으므로 **버린다**(카드가 플레이스홀더로 뜬다). 이름·좌표는 어차피 `spot_repo`
값으로 덮인다. 구조가 손상된 payload 는 예외 대신 **빈 코스**로 수렴시킨다(상세 화면 500 방지 —
프론트에 "표시할 스팟 정보가 없어요" 분기가 이미 있다).

### `/mine` 도 동일 적용
`POST /courses/mine`(`SaveCourseRequest` → `ai_course_repo`)도 같은 재구성을 태우고,
`GET /courses/mine/{id}` 는 읽기 필터를 태운다. 본인만 읽는 보관함이라 피해자가 자기 자신뿐이지만,
저장소에 무검증 JSON 이 쌓이면 나중에 상세 화면을 만드는 순간 그대로 표면이 된다.

### 응답 shape 호환
재구성 결과를 실제 `CourseResponse`/`CourseSpot` pydantic 모델로 검증해 통과함을 확인했다.
프론트가 쓰던 접근 경로(`course.spots[].name`, `course.legs[i].walk`, `course.region.region_name`)가
그대로 살아 있어 **프론트 컴포넌트 수정은 불필요했다**(A-6 때문에 고친 프론트 파일 없음).

### 눈에 보이는 동작 변화 (의도된 것)
1. 공유 코스 상세의 혼잡도 배지가 "공유 시점"이 아니라 **현재 값**으로 뜬다(원천 실패 시 배지 없음).
2. "이래서 추천했어요" 칩이 registry 코드 원문만 남는다(원래도 라벨 복원이 불가능해 코드가 보였다).
3. 이 배포 **이전에** 만들어진 공유 코스는 사진·설명이 사라지고 플레이스홀더가 된다.

## 4. 못 한 것 / 남은 리스크

| 항목 | 이유 |
|---|---|

| `legs` 를 서버에서 재계산 | 구간마다 Tmap 실호출(최대 14콜)을 UGC 쓰기 경로에 얹게 된다. legs 에는 텍스트·URL 이 없어 위조 가치가 낮다고 판단해 **숫자·좌표 구조 검증 + clamp** 로 갈음했다. 조작해도 "도보 3분" 같은 이동시간 왜곡이 한계다 |

| 과거 공유 payload 정리(마이그레이션) | 읽기 필터로 노출을 차단했으므로 DB 는 손대지 않았다. 필요하면 관리자 콘솔에서 개별 숨김 |
| `security.txt` 의 `Contact` | 전용 보안 신고 창구가 없어 개인정보처리방침 §9 문의처를 재사용했다. 별도 주소를 만들면 이 파일만 고치면 된다 |

### 저장소 상태 주의 (커밋 전 확인)
작업 중 **다른 세션이 동시에 편집한 슬랙 연동 변경**이 워킹트리에 함께 있다:
`backend/app/config.py`, `backend/app/middleware/error_alert.py`, `backend/app/services/slack_notify.py`(신규).
이번 감사 반영과 무관하므로 **건드리지 않았다.** 커밋 시 분리 여부를 판단할 것.

## 5. 배포 담당자가 수동으로 해야 할 것

1. **운영 `.env` 의 `ADMIN_SESSION_SECRET` 확인** — 없으면 생성해 넣는다.
   `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` → `deploy/.env` →
   `docker compose up -d backend` → `docker compose logs backend | grep ADMIN_SESSION_SECRET` 가
   **아무것도 출력하지 않아야** 한다. (안 넣으면 방문 통계가 조용히 0 이 된다 — fail-closed)
2. **실키로 HTTPS 실호출 1회 확인** — 원천 BASE_URL 을 https 로 바꿨으므로, 배포 후
   `docker compose logs backend | grep -i "비정상 상태코드\|호출 실패"` 가 늘지 않는지,
   홈 화면 사진·혼잡도·날씨가 정상인지 눈으로 한 번 본다. (공공데이터포털은 https 를 지원하지만
   운영 방화벽/프록시 사정은 실환경에서만 확인된다)
3. **DNS SPF/DMARC 설정** — 도메인 사칭 메일 방지. 감사 지적사항이며 코드로 할 수 없다.
4. `docker compose pull && docker compose up -d ollama certbot` 후 컨테이너 정상 기동 확인
   (태그 고정으로 ollama 가 예전 `latest` 대비 올라갈 수 있다).
5. 배포 후 `https://sumeungil.co.kr/.well-known/security.txt` 가 200 으로 열리는지 1회 확인.

## 6. 핸드오프 노트 (QA 가 특히 볼 곳)

1. **공유/저장 코스 쓰기·읽기 경로 전체** — 기존 코스를 실제로 공유해 보고, 상세 화면에 스팟 이름·
   사진·혼잡도가 정상으로 뜨는지(그리고 이전에 만든 공유 링크가 500 없이 열리는지) 확인. 없는 스팟
   id 를 섞은 요청이 400 INVALID_COURSE 인지도 함께.
2. **방문 집계 fail-closed** — `ADMIN_SESSION_SECRET`/`JWT_SECRET_KEY`/`ADMIN_PASSWORD_HASH` 가
   전부 빈 환경에서 집계가 꺼지고 경고가 **1회만** 찍히는지, 키가 있으면 종전대로 세어지는지.
   90일 정리 루프는 기동 직후 1회 도므로 첫 로그를 확인.
3. **관리자 로그인** — 이름 입력칸이 드롭다운 대신 텍스트로 뜨고, 정확한 이름+비밀번호로 로그인되며,
   틀린 이름이 비밀번호 오류와 **구분되지 않는 401** 인지. `ADMIN_OPERATORS` 미설정 시 이름칸이
   아예 안 뜨는지도 확인.
