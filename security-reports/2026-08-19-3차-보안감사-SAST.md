문서와 코드는 이번 회차에 전부 정비됐습니다(위 "반영 확인" 참고). **남은 건 실제 운영 `.env`에 값이 채워졌는지 확인하는 것뿐**입니다. 결과가 0건이 아니라면(경고가 뜬다면) 즉시 값을 채워 넣으세요.

### 3. `ShareCreateRequest.course` 스키마 자체 강화 (심층방어, 시급하지 않음)
**파일**: `backend/app/schemas/community.py:128,153`

현재는 `course_payload.py`의 서비스 레이어가 클라이언트 값을 무시하고 스팟 ID로만 서버값을 재조립해서 실질적으로 안전합니다. 다만 스키마 타입 자체(`dict[str, Any]`)가 여전히 느슨해서, 나중에 서비스 레이어 로직을 실수로 건드리면 방어가 재발할 수 있는 단일 장애점입니다. 여유 있을 때 스키마를 `list[int]`(스팟 ID 배열) 중심으로 좁히는 리팩터링을 권고합니다.

## 🟡 확인/설정 (배포 담당자, 코드 아님)

### 4. DNS에 SPF/DMARC 레코드 추가 — 2차부터 이월
가비아 DNS 관리 콘솔:
```
TXT  @              v=spf1 -all
TXT  _dmarc         v=DMARC1; p=none;
```

### 5. TMap 앱키 도메인 제한 확인
SK Open API 콘솔에서 `NEXT_PUBLIC_TMAP_APP_KEY`에 리퍼러/도메인 화이트리스트가 걸려 있는지 확인(코드 자체는 문제 없음, 콘솔 설정 확인만 필요).

### 6. 인증서 자동갱신 성공 여부 확인 후 HSTS 적용
`nginx.conf` 133-135행 계획대로, 자동갱신이 1회 이상 성공한 게 확인되면 그때 HSTS를 켜세요. 아직 확인 전이면 지금은 손대지 마세요.

### 7. CSP 강화 (여유 있을 때)
`Content-Security-Policy: frame-ancestors 'self'` 뿐이라 XSS 심층방어가 없습니다. Next.js 인라인 스크립트·Tmap SDK·관광공사 이미지 도메인 전수조사 후 `script-src` 추가.
